# Pneumaris site audit — October 12, 2026

Audited the six public routes of [pneumarisband.com](https://pneumarisband.com/)
and repository commit `803e798`, site/package version 1.14.0. This pass organized
the local asset library and corrected documentation; site behavior remains at
the audited version. Findings are filed in GitHub for a subsequent remediation pass.

## Evidence and method

- Source review: pages, shared layout/header/footer/consent, global CSS, image
  optimizer, site config, build configuration, lockfile, and response headers.
- Read-only live HTTP checks: six canonical pages, robots, both sitemaps,
  missing route, no-slash variants, and HTTP/www redirects. See
  [HTTP snapshot](2026-10-12-http.json). Reproduce with
  `node scripts/audit-http.mjs <output.json>`; it makes bounded public GET requests.
- Chrome: rendered JSON-LD and accessibility tree, keyboard navigation,
  artwork open/Tab/Escape, empty-form feedback, preference reopen/close,
  computed colors/link styling, images, and 320/390 CSS-pixel layouts.
  Desktop viewport override was reset after testing.
- `npm run build` passed, producing six static pages and sitemap output.
  `npm audit --json` reported 17 affected packages: 2 critical, 14 high, 1 low.
  See [dependency snapshot](2026-10-12-dependencies.json).
- [Structured findings](2026-10-12-findings.json) preserve observed evidence and
  remediation criteria independently of the issue tracker.

Representative reproducible observations:

- Missing-route GET returned 200, homepage title/H1, and homepage canonical.
- At 390px, the closed menu had height 0 and opacity 0 while Home held focus.
- Opening the lightbox with Enter left focus on its trigger; Tab reached the
  background SoundCloud link, and Escape left focus there.
- Muted `#5e574f` contrast is at most 2.95:1 against black, below the 4.5:1
  requirement for small text and 3:1 for functional icons. Dim gold at 50%
  opacity is about 2.57:1 over black. These are calculated colors, not sampled
  antialiased screenshot pixels. See [WCAG contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).
- At 320px, contact client width was 305px with a scrollbar, document width
  320px, and the 302px CAPTCHA ended at x=319.59px. About, Extras, and Privacy
  had equal client/document widths of 305px under the same conditions.
- Pleroma's Hollow Constellations was `PT2M30S` in first-party JSON-LD and
  04:47 in Spotify; The Shape's Static Halo was `PT2M28S` vs 05:13. All 14
  durations across those two releases differed in the observed players.

## Checks that passed

- All six intended routes returned 200 with unique titles/descriptions, one
  first-party H1, English language, viewport metadata, and self canonicals.
- Robots permits crawling and points to the matching sitemap index. The
  sitemap contains exactly the six canonical, reachable routes.
- No-slash routes redirect with 308 to slash routes. Tested HTTP and www
  `/music/` variants redirect directly to HTTPS apex while preserving the path.
- Home's WebSite/MusicGroup and music's five MusicAlbum graphs are present
  in rendered DOM and parse as JSON. Artist references use the canonical @id.
  This verifies presence/syntax, not external rich-result eligibility.
- Local displayed images have alt text and dimensions; the wallpaper download
  returned 200 with the expected 5,445,023-byte PNG. The empty lightbox image
  is a dynamic modal exception requiring review with its modal fix.
- Live responses contain enforced CSP, HSTS, nosniff, referrer policy,
  frame protection, COOP, and restricted browser permissions. Public static
  `Access-Control-Allow-Origin: *` is not an authenticated-data exposure here.
- Contact controls have labels/autocomplete where relevant; status updates use
  a live region. CAPTCHA loads without observed console CSP errors.
- The GA executable loader is absent before acceptance/after decline, based on
  source and live script inspection. Cloudflare's independently injected beacon
  and Google Fonts are present and described separately in the policy.
- The skip link resolves to `#main`. Page-entry animation is gated by reduced
  motion. External new-tab links use `noopener noreferrer`.
- Contact error text uses `textContent`; CAPTCHA tokens reset after a completed
  request path. No contact submission or CAPTCHA solution was performed.

## Security landscape and scope

As of this audit, [OWASP Top 10:2025](https://owasp.org/Top10/2025/), current CSP
guidance, and WCAG 2.2 AA provide the review baseline. Static HTML can use
hashes or external scripts to restrict executable inline content; a fixed
build-time nonce is inappropriate. Current threats relevant here include
[Windows Vite file disclosure](https://github.com/vitejs/vite/security/advisories/GHSA-fx2h-pf6j-xcff)
and conditional [Astro AVIF processing RCE](https://github.com/withastro/astro/security/advisories/GHSA-26w7-cxv4-gfx2).
The former intersects this repo's `host: true`; the latter requires processing
attacker-controlled AVIF, absent from the current static Pages request path.
Current registry/advisory research shows the installed toolchain predates fixes;
do not blindly translate npm severity totals into production exploitability.
Practitioner guidance favors static-script hashes and inspection of actual
vendor loading, with stable-resource SRI where applicable. See
[strict CSP](https://web.dev/articles/strict-csp),
[third-party scripts](https://cheatsheetseries.owasp.org/cheatsheets/Third_Party_Javascript_Management_Cheat_Sheet.html),
and [Pages header limits](https://developers.cloudflare.com/pages/configuration/headers/).

| OWASP category | Result for this static site |
| --- | --- |
| A01 Broken Access Control | No first-party protected endpoints/database or SSR request handling; provider account controls unverified |
| A02 Security Misconfiguration | Live headers present; inline-script permission and dev network exposure recorded |

| A10 Mishandling of Exceptional Conditions | Fetch/JSON failures handled and tokens reset; required-field feedback gap recorded; no backend failure testing |

Public Web3Forms access and hCaptcha site keys are browser integration identifiers,
not evidence of a leaked private credential. No credentialed attack, destructive
probe, private-history secret scan, or penetration test was performed.

## Limits and follow-up verification

This is source/HTTP/manual Chrome review, not WCAG certification. No axe scan,
NVDA/JAWS/VoiceOver pass, text-spacing stress test, or physical device test was
run. The 320px reflow check approximates a narrow high-zoom layout; actual
400% browser zoom still needs verification during remediation. Third-party
player/CAPTCHA internals were observed but not fully accessibility-tested.

Search Console indexing/queries, backlinks, GA reports, real-user Core Web
Vitals, Lighthouse, and Cloudflare/Web3Forms account settings were not accessed.
No ranking loss, field performance failure, or provider-side CAPTCHA bypass is
claimed. Short generic About/Contact descriptions are an editorial opportunity,
not a demonstrated indexing defect, and were not inflated into issues.

After fixes, run a clean build, repeat the relevant browser checks, and verify
production HTTP headers/statuses. Astro dev does not serve `public/_headers`.
