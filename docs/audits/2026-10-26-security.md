## Application hardening

[PR #23](https://github.com/jmusick/pneumaris/pull/23) addresses the two open
security audit issues:

- [#9](https://github.com/jmusick/pneumaris/issues/9): remove `unsafe-inline` from
  `script-src`, explicitly block event-handler attributes, externalize the consent
  loader using Astro's processed scripts, and pass the analytics ID through an
  escaped data attribute. Disable small-bundle inlining for all application
  scripts. Keep inert JSON-LD and the existing vendor origin permissions.
- [#10](https://github.com/jmusick/pneumaris/issues/10): scope the consent promise
  to Google Analytics, explain independent Google Fonts requests, remove the
  nonexistent close-banner instruction, and date the privacy policy October 26.

Astro 7.4.2 raises its Node minimum to 22.23.4 for the October security fixes.
Align `engines.node`, add a `.node-version` build pin, and correct the README's
previous 22.12.0 deployment advice. Synchronize the package/footer version to
1.17.1. See the [Astro release notes](https://github.com/withastro/astro/releases/tag/astro%407.4.2)
and [Cloudflare build image documentation](https://developers.cloudflare.com/pages/configuration/build-image/).
